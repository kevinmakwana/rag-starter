# Demo Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `DEMO_MODE=true` turns the API into a read-only public demo: visitors can ask questions over the Acme sample documents (seeded at startup) and nothing else, a global daily cap bounds spend, and the web app presents itself as a demo.

**Architecture:** Two new global guards bracket the existing rate limiter: `DemoModeGuard` (deny by default: only reads and `@DemoSafe()` routes pass) runs before it, and `DemoBudgetGuard` (global per-UTC-day question cap) runs after it, so only admitted requests spend the budget. A shared `seedSamples()` function (extracted from `seed.ts`) is run at startup by a `DemoSeeder`. `/health` reports `demo`, and the web page hides every write control and shows a banner plus starter questions.

**Tech Stack:** NestJS 12, Express, Jest 30 (ts-jest ESM), Next.js 16, Node's built-in test runner for `apps/web`.

**Spec:** `docs/superpowers/specs/2026-10-29-demo-mode-design.md`

## Global Constraints

- `DEMO_MODE`: `true` or `false` (default `false`, case-insensitive); anything else is a startup error naming `DEMO_MODE`. `DEMO_MAX_QUERIES_PER_DAY`: whole number, default `500`, `0` = no cap; invalid values are startup errors naming the variable.
- With demo mode off, behaviour is unchanged: every existing test must pass untouched.
- Guard order, exactly: `AuthGuard`, `DemoModeGuard`, `RateLimitGuard`, `DemoBudgetGuard`.
- Demo mode allows `GET`/`HEAD`/`OPTIONS`, `@Public()` routes and `@DemoSafe()` routes; everything else answers `403` with the message "This is a read-only demo: uploading, editing and deleting are turned off."
- Daily cap exhausted: `429`, message "The demo has reached today's question limit. Please try again tomorrow.", `Retry-After` = whole seconds to the next UTC midnight (at least 1). Only requests admitted by the rate limiter, on `@DemoSafe()` routes, count.
- Dev runs with `ts-node --transpile-only` (no decorator metadata): every injected constructor parameter needs an explicit `@Inject(...)`.
- Database-backed specs live in `apps/api/test/api.e2e.spec.ts` only (parallel Jest workers race in `migrate()`); new DB tests are added there as another top-level `describeIfDb`.
- Never pipe a gating command (`tsc`, `npm test`) through `tail`/`head`: a pipe hides the exit code. Redirect to a file and check `$?`.
- No new dependencies and no lockfile changes. `apps/web` tests use `node --test` with a `.mjs` test file importing `../lib/*.ts` (Node 22.18+ strips the types; no constructor parameter properties or enums in `lib/`).
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Rulings (made while writing the plan)

- **Seeding blocks startup.** `DemoSeeder` awaits `seedSamples()` in `onApplicationBootstrap`, so the first request after "listening" always sees the samples and tests are deterministic. Two small documents embed in a moment, and a restart is idempotent (nothing re-embedded). A failure is logged and does not stop the API. Cost if wrong: a slow embedding provider delays the first start; switch to fire-and-forget.
- **`demo` is optional in the web `Health` type** (`demo?: boolean`), so the web app still works against an API that predates the field.
- **The "Authentication is OFF" startup warning is skipped in demo mode**, where open reads and an enforced read-only boundary are the intent; a demo log line replaces it.

## Review Focus

Failure modes the spec implies; each has a test in the task that owns the code.

1. A route added later with no marker must be blocked in demo mode (classification test, Task 3; probe test, Task 2).
2. Refused writes and rate-limited requests must not spend the daily budget; refused writes must not spend rate-limit budget (Task 2).
3. With `API_KEYS` set as well, a missing key is `401` before any `403` (Task 2).
4. A seeding failure at startup must not stop the API, and a second start must add no documents (Task 4).
5. The cap must reset at the UTC day boundary and report an accurate `Retry-After` (Task 2).

```ts
import { DailyBudget } from '../src/demo/daily-budget';

describe('DailyBudget', () => {
  const clock = (start: number) => {
    let now = start;
    return { now: () => now, advance: (ms: number) => (now += ms) };
  };
  const NOON = Date.UTC(2026, 9, 29, 12, 0, 0);

  it('allows up to the cap in a day, then refuses', () => {
    const budget = new DailyBudget(clock(NOON).now);

    expect(budget.take(2).allowed).toBe(true);
    expect(budget.take(2).allowed).toBe(true);
    expect(budget.take(2).allowed).toBe(false);
  });

  it('tells a refused caller how many whole seconds remain until the next UTC midnight', () => {
    const time = clock(Date.UTC(2026, 9, 29, 23, 59, 0));
    const budget = new DailyBudget(time.now);
    budget.take(1);

    expect(budget.take(1)).toEqual({ allowed: false, retryAfterSeconds: 60 });

    time.advance(59_500); // 500 ms to midnight
    expect(budget.take(1)).toEqual({ allowed: false, retryAfterSeconds: 1 });
  });

  it('starts a fresh budget on the next UTC day', () => {
    const time = clock(Date.UTC(2026, 9, 29, 23, 59, 0));
    const budget = new DailyBudget(time.now);
    budget.take(1);
    expect(budget.take(1).allowed).toBe(false);

    time.advance(60_000);

    expect(budget.take(1).allowed).toBe(true);
  });

  it('does not count a refused request', () => {
    const budget = new DailyBudget(clock(NOON).now);
    budget.take(1);

    for (let i = 0; i < 100; i++) expect(budget.take(1).allowed).toBe(false);
    // still refusing, and nothing overflowed: the next day would start clean (covered above)
    expect(budget.take(1).retryAfterSeconds).toBeGreaterThanOrEqual(1);
  });

  it('never refuses when the cap is 0', () => {
    const budget = new DailyBudget(clock(NOON).now);

    for (let i = 0; i < 1000; i++) expect(budget.take(0).allowed).toBe(true);
  });
});
```

Create `apps/api/src/demo/daily-budget.ts`:

```ts
const DAY_MS = 86_400_000;

export interface BudgetResult {
  allowed: boolean;
  /** Whole seconds until the next UTC midnight (at least 1); 0 when allowed. */
  retryAfterSeconds: number;
}

/** One counter shared by everyone, reset at UTC midnight. In memory: gone on restart. */
export class DailyBudget {
  private day = -1;
  private used = 0;

  constructor(private readonly now: () => number = Date.now) {}

  /** Spends one unit of `cap` for today. A cap of 0 or less means no cap. A refused request is not counted. */
  take(cap: number): BudgetResult {
    if (cap <= 0) return { allowed: true, retryAfterSeconds: 0 };
    const now = this.now();
    const day = Math.floor(now / DAY_MS);
    if (day !== this.day) {
      this.day = day;
      this.used = 0;
    }
    if (this.used >= cap) {
      return { allowed: false, retryAfterSeconds: Math.max(1, Math.ceil(((day + 1) * DAY_MS - now) / 1000)) };
    }
    this.used++;
    return { allowed: true, retryAfterSeconds: 0 };
  }
}
```

```ts
import { CanActivate, ExecutionContext, ForbiddenException, HttpException, HttpStatus, Inject, Injectable } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { IS_PUBLIC } from '../auth/public.decorator';
import { APP_CONFIG, AppConfig } from '../config';
import { DailyBudget } from './daily-budget';
import { IS_DEMO_SAFE } from './demo-safe.decorator';

const READ_METHODS = ['GET', 'HEAD', 'OPTIONS'];

/**
 * Deny by default. In demo mode only reads, public routes and routes marked @DemoSafe() get through, so a
 * write route added later is blocked until someone decides otherwise. Registered after AuthGuard and before
 * the rate limiter, so a refused write costs nothing and spends nobody's budget.
 */
@Injectable()
export class DemoModeGuard implements CanActivate {
  constructor(
    @Inject(APP_CONFIG) private readonly cfg: AppConfig,
    @Inject(Reflector) private readonly reflector: Reflector,
  ) {}

  canActivate(context: ExecutionContext): boolean {
    if (!this.cfg.demo.enabled) return true;
    const targets = [context.getHandler(), context.getClass()];
    if (this.reflector.getAllAndOverride<boolean>(IS_PUBLIC, targets)) return true;
    if (this.reflector.getAllAndOverride<boolean>(IS_DEMO_SAFE, targets)) return true;
    const method = String(context.switchToHttp().getRequest().method).toUpperCase();
    if (READ_METHODS.includes(method)) return true;
    throw new ForbiddenException('This is a read-only demo: uploading, editing and deleting are turned off.');
  }
}

/**
 * One shared per-UTC-day cap on questions. Registered last, after the rate limiter, so only requests that
 * were admitted count: a visitor who is refused (by either guard) cannot use up everyone else's budget.
 */
@Injectable()
export class DemoBudgetGuard implements CanActivate {
  private readonly budget = new DailyBudget();

  constructor(
    @Inject(APP_CONFIG) private readonly cfg: AppConfig,
    @Inject(Reflector) private readonly reflector: Reflector,
  ) {}

  canActivate(context: ExecutionContext): boolean {
    if (!this.cfg.demo.enabled) return true;
    const targets = [context.getHandler(), context.getClass()];
    if (!this.reflector.getAllAndOverride<boolean>(IS_DEMO_SAFE, targets)) return true;

    const result = this.budget.take(this.cfg.demo.maxQueriesPerDay);
    if (!result.allowed) {
      context.switchToHttp().getResponse().setHeader('Retry-After', String(result.retryAfterSeconds));
      throw new HttpException(
        "The demo has reached today's question limit. Please try again tomorrow.",
        HttpStatus.TOO_MANY_REQUESTS,
      );
    }
    return true;
  }
}
```

```ts
import { Logger } from '@nestjs/common';
import { readdir, readFile } from 'fs/promises';
import { extname, join, resolve } from 'path';
import { titleFrom } from '../documents/documents.dto';
import type { DocumentsService } from '../documents/documents.service';

/** The repo's /samples folder, as seen from apps/api (where npm runs the scripts and the API). */
export const defaultSamplesDir = (): string => resolve(process.cwd(), '../../samples');

/**
 * Index every .md/.txt file in `dir` for the default user. Skips titles that already exist and content that is
 * already indexed (documents indexed before content hashes were stored have no hash to compare). Returns how
 * many documents were added.
 */
export async function seedSamples(documents: Pick<DocumentsService, 'list' | 'create'>, dir: string): Promise<number> {
  const existing = new Set((await documents.list()).map((d) => d.title));
  const files = (await readdir(dir)).filter((f) => ['.md', '.txt'].includes(extname(f))).sort();

  let added = 0;
  for (const file of files) {
    const content = await readFile(join(dir, file), 'utf8');
    const title = titleFrom(content, file.slice(0, -extname(file).length));
    if (existing.has(title)) {
      Logger.log(`Skipping "${title}" (already indexed)`, 'Seed');
      continue;
    }
    const doc = await documents.create({ title, content, source: `samples/${file}` });
    if (doc.duplicate) Logger.log(`Skipping "${title}" (identical content already indexed)`, 'Seed');
    else added++;
  }
  return added;
}
```

```ts
import { Inject, Injectable, Logger, OnApplicationBootstrap } from '@nestjs/common';
import { APP_CONFIG, AppConfig } from '../config';
import { DocumentsService } from '../documents/documents.service';
import { defaultSamplesDir, seedSamples } from './seed-samples';

/**
 * In demo mode, makes sure the sample documents are indexed before the API starts answering, so a fresh deploy
 * works with no manual `npm run seed`. A restart re-embeds nothing. A failure (say the embedding provider is
 * unreachable) is logged, not fatal: an empty demo that says so beats one that does not start.
 */
@Injectable()
export class DemoSeeder implements OnApplicationBootstrap {
  private readonly logger = new Logger(DemoSeeder.name);

  constructor(
    @Inject(APP_CONFIG) private readonly cfg: AppConfig,
    @Inject(DocumentsService) private readonly documents: DocumentsService,
  ) {}

  async onApplicationBootstrap(): Promise<void> {
    if (!this.cfg.demo.enabled) return;
    try {
      const added = await seedSamples(this.documents, defaultSamplesDir());
      this.logger.log(`Sample documents ready (${added} added)`);
    } catch (err) {
      this.logger.error(`Could not index the sample documents: ${(err as Error).message}`);
    }
  }
}
```

```markdown
### Running a public demo

Set `DEMO_MODE=true` and anyone who can reach the API can ask questions over the sample documents, and nothing else:

- Only reads and the two question routes (`/query`, `/query/stream`) work. Every other route (uploading, editing, deleting, re-indexing, background jobs) answers `403`, including any route added later until it is marked `@DemoSafe()`.
- The files in `samples/` are indexed when the API starts (nothing is re-embedded on a restart), so there is no `npm run seed` step. If that fails, the API logs it and starts anyway; the web app then says the documents are not indexed yet.
- At most `DEMO_MAX_QUERIES_PER_DAY` questions (default 500, `0` = no cap) are answered per UTC day across all visitors; after that the API answers `429` until midnight UTC.
- The web app shows a read-only banner and clickable starter questions, and hides the upload, paste, delete and re-index controls. That is a courtesy: the API is what enforces the rules.

Recommended settings for a demo on a real model: leave `API_KEYS` empty, `RATE_LIMIT_COSTLY_PER_MIN=5`, `TRUST_PROXY=1` behind one reverse proxy, HTTPS, the database not exposed to the internet, and a spend cap at your model provider.

Limits worth knowing: the daily cap protects your bill, not availability. One address can use it all up (at 5 questions a minute that takes about 100 minutes), after which everyone sees "try again tomorrow". The cap and the rate limits live in the API process's memory, so they reset on a restart and several API instances multiply them. Demo mode does not filter what visitors ask.
```
